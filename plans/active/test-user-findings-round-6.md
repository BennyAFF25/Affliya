## Currency investigation — current code, no production verification
- Campaign budget comes from the offer currency and is saved as minor units, e.g. USD 20 → budget_amount 2000 (`promote/[offerId]/page.tsx:1105`, `:1200`; `/api/affiliate/ad-ideas/create/route.ts:61`). Creation checks saved ad-account currency against offer/proposal currency (`create/route.ts:64`). Launch independently checks connected account currency (`app/api/meta/callback/upload-video/route.ts:410`) and passes the unchanged budget to Meta daily/lifetime budget fields (`:814`, `:821`). The selected Meta ad account determines Meta budget/spend currency; setting offer currency does not convert it. Actual connected account currency, invoice billing arrangements, and bank/card FX are unknown. Callback originally records Meta account currency (`app/api/meta/callback/route.ts:130`, `:180`).
- Wallet UI defaults to AUD but can use account settings currency (`app/affiliate/wallet/page.tsx:235`). Top-up accepts requested currency, default AUD (`app/api/stripe/create-topup-session/route.ts:51`); the balance math aggregates numeric ledger values without FX (`utils/wallet/balance.ts`). Do not assume multi-currency wallets are safely implemented merely because a UI setting exists.
- Required launch amount = budget_amount / 100; no currency input or conversion in `getCampaignRequiredFundingDollars` (`utils/paidCampaignLaunchReadiness.ts:35`). Wallet, subsidy and eligible uncommitted launch fund are added numerically; deficit = requiredAmount - effectiveFunding (`:103`). Thus with AUD 15 wallet, no subsidies/fund, USD 20 budget yields numeric required 20 and deficit 5. **USD 20 is treated as 20 AUD-wallet units by this check.** It checks a daily amount or lifetime amount as saved, not a conversion or full daily campaign-duration funding quote. Business launch uses this helper (`app/api/business/ad-ideas/launch/route.ts:248`).
- Submitting proposals reserves no wallet funds (`promote/[offerId]/page.tsx:1296`). Readiness excludes launch funds committed elsewhere (`utils/paidCampaignLaunchReadiness.ts:84`); campaign-live marking reserves an allocation by campaign ID without conversion (`utils/launchFund.ts:318`, `:333`, called from `upload-video/route.ts:1227`). Existing reserved activation subsidies likewise enter readiness numerically (`paidCampaignLaunchReadiness.ts:70`). None of these paths establishes an FX-backed reservation.
- Insights parse Meta spend directly and persist it to live_ads (`app/api/meta/ad-insights/route.ts:181`, `:189`; auth untouched). Settlement computes unpaid = spend - spend_transferred (`utils/adSpend/settlements.ts:340`), applies subsidy/wallet numerically (`:409`, `:436`), writes wallet deduction (`:565`), and transfers rounded amount × 100 with hardcoded `currency: "aud"` (`:864`). No FX conversion is visible in this chain. For a USD Meta account, numeric USD spend is therefore deducted/reimbursed as the same numeric AUD amount. Stripe/bank conversion after that transfer cannot correct the platform's missing USD→AUD calculation.
- Historical LR-004 atomic RPC claims conflict with current multi-query helper; historical reports are not proof of deployed runtime. No database/account evidence queried.

## Interest-search token requirements and limits
- Picker debounces 350ms and calls `/api/meta/interests` with offerId and query (`MetaInterestPicker.tsx:25`). Route requires session, affiliate role, existing offer/business association (`app/api/meta/interests/route.ts:11`, `:25`), prioritizes trimmed server-only `META_TARGETING_SEARCH_TOKEN` (`:34`), otherwise selects matching business/page/ad-account token (`:35`). It calls `GET https://graph.facebook.com/v26.0/search?type=adinterest&q=…&limit=15` with Bearer authorization (`:55`), returns numeric IDs + labels only, and returns 502 if Meta rejects the token (`:64`). No configured token is exposed to the browser.
- Existing supported repository token source is the business OAuth user access token exchanged/stored by `/api/meta/callback`. OAuth requests `ads_read`, `ads_management`, `business_management` and Page permissions (`app/api/meta/start/route.ts:10`). The environment path treats the token as opaque: **code neither requires nor verifies token type/scopes**. System-user tokens and bare app-access tokens have no repository validation proving acceptance here.
- Operator setup candidate: a valid server-held Marketing API user/system-user access token with advertising read access (`ads_read`; existing OAuth also grants `ads_management`). App/business access eligibility and any account assignments must be verified with Meta. Do not use a Page token, CAPI token, app secret, or assume a bare app token is equivalent. The exact minimum permission set/token types accepted by v26 adinterest search cannot be established from these sources alone. Official Meta docs/token debugger or a separately authorized read-only live test is required. Under “no real external API calls”, no online lookup or token probe was performed; **setting the variable alone is not proof that search works against Meta**.
