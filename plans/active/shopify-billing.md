# Shopify billing

Status: implemented and locally validated after review round 1; staging preparation only. No network, database execution, commits, pushes or deployment authorized.

Problem/product intent: founder explicitly approved App Store-first Free/Growth choice through Shopify Billing (requirement 1.2), preserving nettmark.com Stripe billing and affiliate economics. This extends docs/PRODUCT.md and BUSINESS_RULES.md subscription access rather than replacing commission settlement. Prior review-readiness plan and BILLING-FINDING.md describe billing as undecided; this instruction supersedes that uncertainty.

User impact/success: App Store-first businesses with no Stripe history choose Free or approve Growth in Shopify; existing Stripe/grandfathered businesses keep their route. Connected Shopify-billed businesses can upgrade/downgrade themselves. Only server-confirmed Shopify state grants access.

Existing implementation: choose-plan -> business-subscription routes -> business_entitlements; Stripe sync in utils/businessSubscriptions.ts; grant-first OAuth/pending completion, encrypted refreshable tokens and HMAC lifecycle webhooks under lib/shopify and app/api/shopify. Provider belongs on business_entitlements because getBusinessEntitlement and the SQL campaign gate consume that record. Existing rows default to Stripe. Shopify state is service-only and contains no buyer/customer PII.

Approach: additive migration + exact undo; provider decision and atomic guarded claims; refreshable GraphQL billing; owned confirmation and re-queried webhook reconciliation; provider guards on Stripe endpoints/sync/jobs; extend existing plan UI without new visual patterns; mock regression tests and prescribed offline checks.

Risks/trade-offs: provider transitions must serialize against Stripe customer reservation; ambiguous existing Stripe customer/history stays Stripe conservatively. Pending approvals must be persisted/reused to avoid duplicate creates; uncertain external mutation outcomes fail closed for manual reconciliation. Out-of-order webhooks are hints and requery authoritative state; uninstall uses installation timestamp protection. No deployed schema or Shopify behavior verified. Apply SQL before code in staging, retain data backup; undo only after stopping Shopify billing and reconciling outstanding charges. Undo drops only introduced objects, and must not be used to route live Shopify subscribers back to Stripe.

Price parity: EVERY_30_DAYS and 14-day trial once per business. Query Shopify billing currency: AUD uses SHOPIFY_GROWTH_PRICE_AMOUNT (default 49.00); other currencies use USD only when SHOPIFY_GROWTH_PRICE_USD_AMOUNT is explicitly valid, otherwise Growth refuses with growth_unavailable_currency and Free remains available. UI shows AUD reference pricing and explains Shopify confirms final pricing. Stripe calendar-month/Shopify 30-day parity remains a release review. Test charges unless production plus explicit SHOPIFY_BILLING_TEST=false.

Founder release decision: Shopify recommends Shopify App Pricing (Partner Dashboard managed pricing) for new public apps; requirement 1.2 accepts it or Billing API. We implemented Billing API/manual pricing for custom provider/entitlement integration, accepting responsibility for pricing and lifecycle management instead of Dashboard management.

Rollout order: migration MUST be applied before deploying this code: getBusinessEntitlement selects billing_provider. Rollback requires stopping billing and reconciling outstanding charges first.

## Usage/commission proposal (not implemented)
utils/feeAccounting.ts defaults Nettmark transaction fees to 220 bps. app/api/run-payout charges principal plus fee and transfers principal via Stripe Connect, with idempotency and platform_fee_ledger reconciliation. Wallet topups also include fee and processor passthrough. Subscription provider isolation does not migrate those flows. A Shopify usage pricing line item would need merchant-approved cappedAmount and terms plus appUsageRecordCreate keyed to the existing fee ledger source, cap exhaustion handling, refunds/credits, currency reconciliation, and prevention of simultaneous Stripe fee collection. Affiliate commission principal must still be funded and transferred through Stripe Connect: Shopify app revenue cannot directly settle that liability. This requires a separate commercial/compliance decision and design; no usage records are created here. App Store fee compliance remains a release question, not claimed resolved by recurring subscription work.

Validation: planned typecheck, lint/changed-file ESLint, Shopify billing/integration/pixel and business subscriptions/gate/entitlements suites. SQL reviewed statically only; no migrations executed. Final results recorded below.

Schema evidence: reviewer verified staging growth_trial_used boolean NOT NULL DEFAULT false, growth_trial_started_at timestamptz, required business_entitlement_events.business_email and ensure_business_entitlement insert trigger. Direct SQL references replace legacy to_jsonb hedging. Eligibility requires growth_trial_used=false, no legacy start, no Shopify trial consumption and no stripe_subscription_id. sync_shopify_billing retains its own business_subscription_status_synced audit event, matching Stripe; the existing trigger only logs INSERTs. Stripe recovery changes emit business_billing_provider_changed with from/to metadata.

Implementation details: reserve_stripe_billing sets a durable reservation before any checkout Stripe calls, serialized with provider claim on the entitlement row. An abandoned/failed Stripe attempt conservatively retains Stripe routing; it creates no charge by itself. The claim excludes subscription customer IDs (commission Stripe customers remain separate). Plan mutation claims return the current row so concurrent stale pre-lock reads cannot recreate an approval. Reconciliation is transactional with canonical entitlement audit events and monotonic observations; unchanged replays advance only the observation watermark. Shared Admin GraphQL transport now supports both existing pixel behavior and billing.

Trial policy mirrors Stripe's subscription-history exclusion: creation of a Shopify trial approval reserves that business's one trial; re-opening the same pending approval retains its original 14 days, while declined/cancelled subscriptions do not create a fresh trial. Actual start is recorded on authoritative ACTIVE reconciliation. Trial consumption survives Free and uninstall. Stripe recovery preserves consumed Shopify trials by monotonically setting legacy growth_trial_used under the provider lock; existing trial history is never reset.
