# Segment B

Status: implementation completed; operator database validation pending. Retained at the explicitly requested active path; files only, no SQL execution, Stripe calls, commits or pushes.

Problem: refunds have no pre-Stripe reservation; transfer amount uses selected rather than claimed rows and ignores completion write errors.
Product intent: requested financial integrity preserves AUD economics and existing controls, aligned with VISION, PRODUCT_PRINCIPLES, PRODUCT and BUSINESS_RULES. No UX, Meta auth or campaign changes.
Existing implementation: refund route -> Stripe -> record_wallet_refund; balance.ts and seg7 views subtract embedded top-up amount_refunded. Seg11 mirrors this into the shadow ledger. Transfer queue uses conditional update but an earlier unconditional status write can steal claims.
Approach: service-only refund attempt RPCs serialize on the segA wallet account then top-up, reserve in amount_refunded before Stripe, and atomically finalize audit history or release on definitive failure. Pending ambiguity retains the debit. Transfer worker claims directly, sums returned rows, retains processing batch on ambiguity or persistence failure.
Trade-offs: amount_refunded includes pending reservations; audit history remains completed/accepted refunds only. Pending operations require operator reconciliation; never expire automatically. Separate attempt table avoids changing legacy refund constraints. Existing route authorization is outside this requested change and remains unchanged.
Risks: repository schema evidence only; apply migration before callers. No live schema or database concurrency validation authorized. Unknown Stripe outcomes must not be retried under a new key. Existing settlement watermark/bookkeeping crash gaps remain outside scope.
Success criteria: no concurrent reuse of refund funds, stable external keys, claimed-row transfer sum, no automatic retransfers after accepted/unknown outcomes; rollback-only SQL test instructions.
Validation: local mocked tests, TypeScript, diff check; operator SQL dry run and two-session concurrency procedure supplied, not executed.
