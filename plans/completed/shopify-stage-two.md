# Shopify automatic tracking

Status: completed (local implementation and offline validation; release checks remain). Offline only; no commits, pushes, deploys or database connections.

Problem / product intent: connected Shopify merchants still paste a Customer Events snippet. Automatic attributed sales advance VISION.md and PRODUCT_PRINCIPLES.md's simpler measurable distribution, preserving PRODUCT.md / BUSINESS_RULES.md participation, scoped commissions and all money semantics.

Existing implementation: lib/shopify, ShopifyConnectCard, /go/[ref], campaignIdentity, track-event, process-conversion, conversionScope and auth_rate_limit_hit. Redirect now sends stable affiliate UUID, no click ID. Processor checks participation/paid approval, product scope, amounts in major units, recurring terms and payout idempotency. Existing ingestion does not verify orders; no read_orders is authorized. Generic tracker localStorage has no expiry despite seven-day cookies (docs/TRACKING.md); new extension explicitly expires attribution after seven days without changing generic tracking.

Approach: strict marketing-consent app pixel; allowlisted purchase ingress with store, campaign/offer ownership and participation checks; atomic order dedupe + existing event ledger insert via service-only SQL function; invoke existing process-conversion handler locally without an HTTP hop. No commission logic changes. Lifecycle activation is best effort, status/retry owner-only, deletion precedes revoke, redaction purges order dedupe. Existing manual snippet remains a legacy path; merchants must remove it when switching to prevent cross-path duplicates.

Success / user impact: Connect attempts tracking activation, connected card shows tracking state/retry, attributed purchases enter the existing pipeline once per shop/order. No buyer PII, IP or user-agent stored. Scope remains exactly read_products,write_pixels,read_customer_events.

Risks / trade-offs: browser assertions are unverified; consent and browser delivery can suppress events; no guarantee of processor completion after a crash (same handoff limit as existing path). Atomic SQL prevents orphan dedupe reservations and concurrent double event insertion. Shopify CLI extension/API validation and applied schema are unknown offline. Local main inspected, no remote refresh permitted. No product conflict identified.

Validation: baseline `yarn -s typecheck --incremental false`: zero TS errors. Mock route/lifecycle/ingress/privacy/rate-limit/concurrency tests, existing Shopify/tracking checks, changed-file lint and offline build planned. SQL prepared only, not applied.

Changed-file ESLint passes (existing React-version configuration notice only).
